## Failures to hand back

1. **Arrow keys do not change selection (DOD-08, BR-14).** WAI-ARIA radio-group pattern and DOD-08 expect arrows to move focus *and* check. Observed in both groups: focus moves, `aria-checked` stays. Source of behaviour is the reka-ui `RadioGroupRoot` / `RadioGroupItem` used via `components/ui/radio-group`; not diagnosed further here.
2. **Light theme: sublabel on the checked tile 4.27:1 (DOD-08/09, BR-11).** `text-muted-foreground` on `bg-accent` in `:root` roles (`--muted-foreground: graphite-550` on `--accent: graphite-100`). Dark theme passes (4.75:1).

## Re-run (DOD-08, DOD-09 only)

### Failure 1 — root cause: test method, not code

reka-ui docs (Context7 `/unovue/reka-ui`, RadioGroup → Keyboard Interactions) and the installed `reka-ui@2.11.0` `RadioGroupItem.js` agree: the item sets `isArrowKeyPressed` on `keydown`, clears it on `keyup`, and on focus runs `setTimeout(0)` → `click()` only while the flag is still set. `playwright-cli press` sends `keydown` + `keyup` back-to-back, so `keyup` cleared the flag before the timeout fired. With separate `keydown` / `keyup` (real key timing) arrows move focus **and** select. No change to `components/ui` or `OptionTile` for this item. "Tab lands on `Black`" in the first run was a consequence: roving focus remembers the last focused item, which is the checked one once arrows select.

Keyboard log (1440, Empty → arrows via `keydown`/`keyup`):

### Failure 2 — fix

`OptionTile.vue`: sublabel of the checked tile uses `group-has-[[data-state=checked]]:text-foreground/65` (unchecked keeps `text-muted-foreground`). No token change (BR-15). Candidates measured in the browser before choosing: `/60` = 5.06 dark / 4.72 light; `/65` = 5.70 / 5.57; `/70` = 6.32 / 6.63.
